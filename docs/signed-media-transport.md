# 媒体签名与范围续传

正式分片链的时间戳保留模式使用本机 HTTP 中转，FFmpeg 从中转解码；原课程选择和播放回退链不变。直接读取旧签名在现场检查中出现初始 HTTP403，完整重新签名后能读取 109 分钟附近的实际 AAC 音频包。后续完整隔离运行通过 217 个范围请求获取约 1.81 GB 媒体，解码出约 109 分钟音频并完成识别。
这验证修复后的完整获取，仍不能据此确定旧失败输入提前 EOF 的唯一根因。

中转仅监听 127.0.0.1，使用随机路径，签名、Cookie 和源 URL 不写审计。首次以新签名读取最多 64 KiB 的媒体头，随后按最多 8 MiB 的封闭字节范围获取。每个上游请求重新生成 t 与 clientUUID，保留选定媒体路径和非认证查询参数；不重新选课或调用模型。正式下载先检查一次已有 SSO；仅显式配置恢复工厂的入口允许在旧会话失效后使用现有配置启动一次新认证。核对原用户与租户后从未读位置续传，不跟随媒体跳转、不重放 CAS 票据。只读诊断默认禁止刷新及新认证。

上游范围须返回精确的 206/Content-Range 和一致的文件总长度。固定强 ETag 或 Last-Modified，并在每个请求中使用相应 HTTP 条件；响应标识变化立即失败。缺少可用标识时拒绝续传，不能凭相同文件长度拼接结果。Last-Modified 的证据强度受服务器时间精度限制；它不是完整文件的密码学哈希。

短读、网络故障或有限的暂时性 HTTP 错误最多尝试三次。已经收到的字节留在当前有界缓冲中，新请求从下一未读字节开始；验证完成后才交给 FFmpeg，不重复输出已收到字节。首次字节重试等待真实时钟推进后再签名，不伪造未来时间。没有盲目重放旧票据或在失败时清空既有音频。

中转始终保留源字节顺序；解码继续使用 `aresample=async=1:first_pts=0` 处理真实时间戳间隙。原 FLAC 哈希、VAD、分块、全局去重、云端整课额度以及数据库/发布/邮件开关不变。FFmpeg 结束或课次释放后关闭中转。传统不保留时间戳的提取路径保持原行为。

`audio_diagnostics.source_transport` 保存范围请求数、重试数、读取字节数、文件总长、标识类型和固定错误码，以及安全的跳转类别、Cookie 更新次数和会话刷新结果。即使 FFmpeg 返回 0，只要中转发生不可恢复错误，或原有读取/时长完整性检查失败，就不能建立 ASR 计划。诊断结束仍保留已经解码的失败输入。

## 模块边界与恢复决策

- `src/runtime/media_protocol.py` 管理选定媒体和实际请求目标的身份、响应范围/长度/ETag 校验、固定重试决策，以及已验证字节缓存。它不登录、发网络请求、读写文件或调用模型。
- `src/runtime/media_transport.py` 管理签名、HTTP Session、Cookie、一次会话刷新、本机中转及资源关闭。签名、请求、校验、读取、恢复和重试分别记录阶段；失败同时保留具体原因和未读字节偏移，不仅给出“重试耗尽”。
- `src/runtime/audio_preparation.py` 集中 PCM 采样规格、准备期限、解码诊断和完整性门禁。生产入口只负责保留音频、绑定课程检查点和后续处理。

同一范围最多三次尝试，包括刷新后的请求。短读、连接故障、超时、有限暂时 HTTP 错误或未履行的范围请求可重试；401 或可信登录跳转只能触发一次会话恢复（旧会话检查及最多一次新认证）。未知跳转、源身份变化、非法范围和长度不能通过重试放行。错误诊断按异常类型分类，不保存服务端错误文本或私密 URL。传输 `state` 描述最近范围的处理阶段，不表示整堂课已获取完整；`terminal_error_code` 在关闭后仍保留。

WebVPN 包装后的复旦 SSO 登录入口按配置生成的完整地址精确匹配；不能仅凭代理路径末尾含有 `login` 就认为可信。命中后仍只通过原配置恢复会话、验证原登录用户并在同一字节偏移重新签名，不访问跳转中的票据。`last_redirect` 只记录目标是否同源、是否为已知 SSO、路由类别、是否降级/携带用户信息以及查询串是否存在，不记录主机、具体路径、票据或查询值。此分类遗漏已通过本地真实 HTTP 测试复现和修补；此前云端未知 302 的具体目标未保留，不能据此宣称它的根因已经确认。

同源原生 WebVPN 控制路由或门户根路径的未知跳转，可在正式下载中触发一次原门户/API 健康检查。该目标不会被跟随、用作替换媒体或认定为已登录；只有检查原用户成功、从原偏移重新签名并取得源身份不变的合法 206 才续读。代理到未知站点的编码路径、外站、降级和带用户信息的地址仍拒绝。持续跳转、用户改变或 ETag 改变立即失败，保留已获取输入。

## 认证可用性与校园本地诊断

`src/api/auth_recovery.py` 在提交凭据前有界检查门户，仅对网络超时/连接故障、临时服务故障和明确的冷会话等允许重试。默认至多三次，每次新建 Session、取得新票据；失败 Session 及时关闭，不重放票据。凭据拒绝、缺少密码认证方式、TLS 校验错误和程序错误不自动重试。必须通过严格 iCourse API 登录检查才返回客户端，HTTP200 页面本身不算认证成功。

GitHub Actions 的默认入口始终创建 WebVPN 会话，没有直连自动回退，也不修改定时规则或 Secrets。校园本地诊断可显式创建 `WebVPNSession(access_mode='direct')` 并用同一严格 CAS 流程直接认证 iCourse；该模式跳过 WebVPN 密码登录，票据只能返回配置的 iCourse 站点，媒体 Cookie 按域名/路径筛选。仅首页可达或受控测试通过不能视作真实登录/整课获取通过，校园模式也不能作为云端可用性的证据。

HTTP 来源比较采用协议、主机和有效端口：HTTPS 的显式 `:443` 与省略端口等价，HTTP 的显式 `:80` 同理。其他端口、不同主机、HTTPS 降级和带用户信息的跳转仍不视为可信登录。真实 WebVPN 门户曾返回同主机 `:443/login`；预检只确认入口可达，严格用户 API 验证仍是认证成功的条件，不直接跟随媒体跳转。

## 同一 Runner 内的有界缓存

正式下载每堂最多缓存 16 MiB、128 个完整验证的范围；LRU 淘汰同时限制字节数和条目数。解码器重新打开已读取区域时，完全包含在缓存范围内的读取可直接返回，不再请求上游。未完成的范围只在当前重试缓冲中续读，不能进入缓存；不会推测拼接多个缓存范围。确认源变更或其他终止错误后，中转拒绝继续输出，包括旧媒体头。关闭时释放缓存，取消期间完成签名也不能重新发起媒体请求。

缓存命中、节省的读取字节和当前缓存大小只以计数记录；`upstream_bytes` 是实际网络读取量，不能与缓存返回量混为一谈。只读检查默认关闭缓存，原读取预算和探测行为保持。缓存不落盘、不上传，也不是跨 Runner 下载检查点：Runner 退出后仍只能保留已经解码的加密失败输入，不能宣称自动恢复整堂下载。跨 Runner 媒体续传需另行设计加密缓存、源身份绑定、配额及过期协议。

## 解码门禁与测试

准备总期限仍为 90 分钟，无 PCM 进展期限仍为 5 分钟。继续保留实际时间戳间隙，不按媒体时长填充尾音。stderr 固定错误扫描支持跨读取边界，即使私密日志尾部已轮换，错误计数也不消失；未知/未完成诊断、非零解码退出、传输终止错误、空音频、非有限时长或未对齐样本均不能进入 ASR。原时长缺口门限保持 `max(120秒, 媒体时长×5%)`，它是拒绝明显不完整输入的检查，不等于已逐字人工确认完整课堂。

本地真实 HTTP 测试覆盖断流后的相同偏移续读、Cookie 更新和删除、一次会话刷新、源变更拒绝、缓存重读、失败范围不缓存和关闭期间取消。真实 FFmpeg 合成时间戳间隙测试验证断流恢复后 PCM 哈希与正常解码一致。CI 同时执行新模块测试和整库测试；受控测试不能替代新代码的真实长课验证。

`inspect_source_metadata` 可有界检查该中转：最多读取 16 MiB，定位两处各最多 64 个音频包；不解码、识别或发布。与本地模拟断流后 PCM 哈希一致的测试共同验证传输机制；有界检查本身不能替代整课验证。
修复后的完整运行记录见 对应的私密验证记录。


## 一次新会话认证与冻结课次复测

资源获取与正式 pilot 的准备入口显式启用新认证恢复；其他客户端、只读诊断和传统提取默认不启用。旧门户/API 检查失败后，恢复工厂只创建一次新 Session 和新的一次性票据，读取现有运行环境配置，不保存密码。认证全过程最多 75 秒，各请求和跳转检查取消标记及剩余期限；超时、取消或用户/租户不符时关闭候选 Session，迟到结果不可采用。新会话归当前下载所有，关闭下载时释放，不替换其他课堂或 PPT 请求的客户端。

恢复认证开始前的无凭据门户预检查，对暂时超时、连接失败或服务不可用最多检查两次，中间等待最多一秒，并计入原75秒期限。TLS错误、不可信跳转、密码拒绝不重试；密码提交和票据跟随开始后不重放原请求。这是同一个恢复流程内的预检查重试，不增加新认证次数或放宽完整性门禁。

认证在每个网络请求之前记录固定阶段，失败审计区分门户预检查、WebVPN上下文/密码提交/票据跟随、iCourse CAS步骤及媒体身份复核，并保留固定异常类型、原因码、预检查次数。即使请求没有收到响应，也能定位失败阶段；不保存异常原文、网址、Cookie或票据。超时和取消的公开审计一旦确定，迟到后台结果不得改写。旧运行只有`fresh_session_exception`的记录无法由后续补丁倒推具体原因。

`source_transport.media_auth` 仅含检查阶段、HTTP 状态及固定失败原因、认证尝试/成功次数。重新认证本身不代表获取通过：恢复后的 206 仍必须满足原媒体路径、长度、范围和 ETag/Last-Modified 校验。FFmpeg 的中转网络等待窗口为 180 秒，以容纳一次有界认证；90 分钟总期限、5 分钟无 PCM 进展和完整性门禁均不变。

资源 workflow 的 `selection_source_run_id` 只接受已结束的同仓库资源运行，解密其冻结选择后重新绑定新运行，不扫描最新课。`resource_slots` 可限制重新验证的课次；后续最多两路并行。旧运行使用原提交，不会因分支更新而应用修补，也不会被新验证覆盖。新一批获取须有用户授权；不对失败音频偷偷重取或自动 rerun。


## 音频启动前的失败证据

首个范围请求失败时也保留中转对象与审计，不能因为未生成PCM就丢弃HTTP状态、固定错误码及未读偏移。后台下载线程将安全失败信息交给调用方，区分媒体查找、范围中转启动、解码器启动；资源入口同时区分初始认证、下载、保留与完整性门禁。最多保存128份当前进程失败记录，重新调度/释放/关闭时清理，不保存原异常消息、URL或traceback，不自动重新获取。旧运行缺失的原因不能由该改动倒推补全。

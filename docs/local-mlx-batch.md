# 本地 MLX 双块调度

在 `plan`、`run` 等子命令之前使用 `--mlx-batch-size 2`；默认1表示串行。选项冻结进计划，恢复时必须保持一致。只改变Mac的MLX原始块调度，不改变GitHub/PyTorch识别：一个bf16模型、真正双路文本解码、音频编码仍串行，固定 `mlx-qwen3-asr==0.4.4`。安装步骤见[本机识别入口](local-history-refresh.md)。

两块各自保持原生低能量不超过30秒的子切块、中文/术语提示、原ASR 2048 token预算、位置、左填充mask及独立EOS。回显沿原去提示补救；截断/超时进入有界单路重试与短段救援，每块独立写检查点。原生形状/OOM错误保留并停止，不盲目重试。恢复时只配对尚未完成的块，单块尾段沿用串行适配器。

组初始时间按两块分摊，保留共享初始耗时和异常，不能将同一次解码计时重复相加。AAC、PPT/OCR、作业视觉证据、完整作业图、摘要和理论自审沿共享流程；`--review-scope full` 才执行旧CPU定位及局部语音复核。切换调度需新计划，不能改变已冻结输入或把原失败改标成功。

本机已有107分钟整堂对照：串行累计解码约19.35分钟，双路组计时约14.62分钟，减少约24.46%。串行前38块来自原检查点且经历暂停，两组整体墙钟和性能采样范围不同；该比例是记录的解码耗时比较。文本有差异，相似度不是准确率，不能由速度结论证明所有机器/课程的质量。双块正式适配保留串行补救，测试覆盖单路异常、超时、原生错误、独立检查点与恢复顺序。

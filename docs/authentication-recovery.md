# 登录前入口暂时故障恢复

课堂准备、课程扫描等主登录入口先做匿名 WebVPN 可达性探测，再开始认证；入口 HTTP 200 或受信登录跳转不代表身份验证成功。首页发生暂时超时、连接错误或服务不可用时，可改用实际 SSO 登录上下文探测；首页不再是唯一否决条件。非暂时拒绝、TLS 错误和不可信跳转仍停止。

SSO 替代探测只对配置中的 IDP 做匿名 GET，最多三跳，不自动跟随跳转，仅读响应头。必须是同一受信协议、主机与端口、无用户信息的已知认证路径，并获得唯一登录上下文；支持复旦实际 `/ac/#/index?...` 格式，不接受任意页面片段或票据跳转。上下文绑定当前 Session，在真正登录时消费一次，不额外重复获取，不作为身份验证成功的证明。

原有认证每轮最多三个全新 Session 尝试，间隔 5、10 秒。如果这一轮的所有失败均发生在入口探测、尚未进入登录流程，且错误为暂时连接／读取超时、连接错误或 HTTP 408/429/500/502/503/504，则等待 30 秒后再开一轮；仍符合条件时，最后等待 60 秒再开一轮。默认最多九个 Session 尝试，入口恢复后仍必须通过 iCourse 严格身份验证。日志显示等待时间及恢复轮次，持续不响应则正常失败并保留检查点。

任何一轮只要曾开始登录流程，就不会触发下一轮延后恢复。认证拒绝、挑战、TLS 错误、不可信跳转或非暂时 HTTP 拒绝不启用这一扩展；原有单轮认证策略保留。媒体续传仍使用独立的单次认证及原有75秒总时限，不使用主登录的多轮恢复；其匿名入口探测最多三次，暂时故障后分别退避5、15秒，等待可取消且受同一个截止时间约束，不重复提交密码。课堂／Worker 并发、音频完整性检查和发布开关均不变。

公开失败审计增加 `precredential_failure`、`preflight_recovery_rounds`、`preflight_recovery_wait_seconds`、`portal_probe_failure` 和 SSO 替代探测的布尔状态，保留最多十条白名单尝试记录；不记录原错误文字、页面、URL、Cookie、登录上下文或账号。`auth_attempts` 统计 Session 尝试数，不是密码提交次数。对自定义大于三次的单轮尝试，上述轮数会缩减，保证总尝试数不超过十次。

媒体恢复的认证异常以 `source_transport.media_authentication` 白名单公开，区分入口超时与身份验证失败；成功认证不等同音频已成功续传，身份和媒体恢复计数分别保留。

本地 HTTP 测试覆盖前三次响应头超时后恢复，以及持续超时、混合登录阶段失败、TLS／跳转拒绝和严格身份验证。它验证客户端策略，不能证明校园服务端或 GitHub 网络出口已恢复。

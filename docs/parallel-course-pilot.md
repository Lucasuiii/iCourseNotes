# Pilot 正式分片处理链

`parallel_pilot.yml` 现在是正式订阅处理链的可复用入口，不依赖基线报告或专用测试课程槽位。
`main` 中的 `check.yml` 调用同一入口；每日只保留台北时间 18:00（UTC+8）主任务，也可手动启动，不再安排晚间补跑。
Pilot 名称为历史保留，当前实现已合并到 main。

## 处理与并发

规划 job 读取现有加密数据库，沿用主程序的课程枚举、日期/节次筛选和学期目录发现，
跳过历史已完成课次、删除标记及达到三次失败阈值的课次。队列只有匿名课次序号，
真实课程与数据库快照放在加密 artifact 内；工作流重试复用原队列，不重新挑选课程。
一次最多 256 个课次；超过时明确失败，避免静默丢课。

默认 `shard_mode=shared` 调用 [全局 Runner 调度](global-runner-pool.md)：一台控制器派发准备、动态 ASR、独立汇总和发布子任务，同时最多十四个子任务，因此处理链含控制器不超过十五台。最多五个活跃课次，同一课程的不同课次也可以占用多个槽位；单堂 ASR 最多六台，空余容量可以补给其他课次。
计划和批次收尾 job 不与本批次控制器重叠。父流程沿用已有数据锁；加密 owner 和派发日志阻止控制器失败后新批次与旧子任务叠加。

Worker 数按 VAD 原块累计时长及历史／本堂实测推理速度估算，以约 75 分钟 ASR 为目标，未完成块不足时减少启动数量。没有历史时使用保守初始估计；不承诺固定提速或完成时间。继续使用原 Silero VAD、约两分钟切片、时间戳和全局去重。

固定 `shard_mode=2` 和 `auto` 仍调用 `qwen_production_lecture.yml`，最多五个课次、每堂最多三台；`auto` 在待识别音频超过 60 分钟时使用三路。保留此入口用于兼容和对照。
本课次全部原块完成且 ASR 子任务结束即可进入 `LectureRunner`，并独立发布，不等待其他课程识别完成；邮件仍在整批收尾按原课程批次发送。
每个子 job 上限 350 分钟，控制器最多协调约 330 分钟。到期不取消子任务，保留派发与检查点，待旧子任务全部结束后重试父工作流恢复；不能把这理解为所有课程共享六小时识别步骤。

准备阶段沿用生产 `AudioDownloader`、认证及播放回退链，不使用基线试验的三小时采样上限。
保存输入哈希、原始块边界和术语；整堂音频及每个块使用无损 FLAC 加密传递。
已知媒体时长有显著缺口时失败，避免把部分输入作为完整课堂发布。
PPT 下载、去重和 OCR 在准备阶段完成，汇总阶段复用 SQLite 中的结果。
官方字幕仅作为有上限的辅助材料，不能覆盖 Qwen 转写。

## LectureRunner、保存与恢复

完整分片经过模型版本、计划哈希、块编号、时间戳和完整性校验后，统一排序及边界去重，
再交给 `LectureRunner.run(prepared_asr=...)`。缺少、重复或未完成分片不允许摘要。
普通内容质量门、无内容处理、摘要、processed_at 与错误清理继续由同一类负责。
历史摘要与已发送记录不会重新生成；删除标记优先。

每次数据库状态转换使用 SQLite backup 保存已提交 WAL 页面，并写入原子替换的加密检查点。
开启发布时，准备阶段还会在 ASR 开始前保存恢复指针；汇总检查点记录对应的 Actions attempt。
摘要失败保留完整转写、时间线、复核状态及错误；重试不重新调用本地 ASR。
同一次 Actions 重试只解码未完成块。开启发布时，下一次正常工作流还可以根据数据库里的
恢复指针读取原准备 artifact 和部分分片，验证后重新绑定本次运行，只识别缺失块。
恢复材料保留 7 天。过期、校验失败或 API 查询失败会明确失败，不当作“没有检查点”重置。
准备音频包不再受旧单包 512 MiB 上限约束：小包兼容原单文件格式，大包使用
每卷最多 64 MiB、总计最多 2 GiB 的认证加密卷，最多 600 个原文件。
清单绑定 run/task/stage、卷序号与整包哈希，完整写入各卷后才原子发布清单。
恢复需下载整个 `qwen-production-prepare-*` artifact，不能仅复制 `prepared.enc`；
缺卷、错卷、篡改或跨 run/task 的输入均拒绝，不重置为新课。旧单文件检查点仍可读取。
ZIP 临时内容只在 Runner 的匿名临时文件中使用，上传的清单和音频卷均已加密。
Runner 突然丢失导致检查点未上传时，还会核对历次汇总步骤；若存在较新的已启动汇总，
却只有更旧检查点或没有检查点，则禁止自动复核恢复，防止无法确认的云端额度被重置。
准备阶段在获取音频前失败时，可以重新尝试准备；成功准备过的输入始终复用。
准备失败另存只含阶段、固定错误码和数值计数的 `qwen-production-prepare-audit-*`，
保留原始异常分类，不让二次检查点保存失败掩盖主错误。若完整输入超过总量／文件数上限，
尽量保留整堂音频和原计划，移除可由原音频重建的重复切片；此诊断回退明确为失败状态，
不会直接启动 ASR 或放宽完整性检查。磁盘／权限故障仍可能阻止保存，审计会区分实际保留结果。
准备读取与 VAD 使用独立的 90 分钟总预算，连续 5 分钟没有新 PCM 才按卡住失败；
健康读取不再被原固定 40 分钟截断。prepare job 最长 120 分钟，为环境安装、音频保留、
切片和 artifact 上传预留时间。失败审计记录总预算、无进展预算和实际经过时间；
超过绝对期限仍停止，并保留不完整输入，禁止用它生成摘要或自动重新获取。

媒体范围请求复用连接和登录 Cookie jar，保留响应中的 Cookie 轮换/删除，并按域、路径和
Secure 属性选择 Cookie。遇到 401 或明确的登录跳转时，正式下载最多用两次有超时的只读
请求刷新现有会话并核对用户身份，再以新签名从未读偏移续传；不会启动密码登录或重放 CAS
票据。会话不可用、未知跳转或源标识变化时停止并保留已有输入。只读媒体诊断默认关闭会话
刷新。安全审计仅记录跳转类别、Cookie 变化计数、刷新结果和失败字节偏移，不记录凭据或 URL。

豆包默认整堂课 900 秒 / 40 段，所有分片共享。VAD 确认有人声但为空/极少字的短区间先补救，
再对有充分原文的疑难片段做引用与强制对齐；两种路径共用同一额度账本。每段在调用云端前先持久化额度预留；
中断导致结果不明时，该段仍计费且不会自动重复调用。完成的复核版本与未解决疑点保留，
摘要重试不会重置额度。无配置、复核失败或位置不确定时继续保留本地原文。
自动词库默认关闭，900 秒 / 18 段仍只属于另行批准的实验配置。
完成课次只保留紧凑审计/额度信息，避免在元数据分片中长期复制完整转写。

## 发布与邮件边界

手动入口默认 `publish_results=false`、`send_email=false`：读取线上存量作为参照，
在临时数据库中验证合并并保存加密产物，不写 data 分支、不调用 SMTP。
当前 main 的日常 `check.yml` 明确开启发布和邮件，沿用日常订阅的原有行为。
`single_run.yml` 的定向重跑/请求/历史替换入口暂时保留原实现。

每个课次的结果只携带该课次、所属课程、PPT 和相应检查点元数据。
发布刷新远端数据库后合并，保留更高重试代际、历史摘要、处理完成状态、删除标记和邮件回执，
同时允许该课次 pending/failed 的 PPT 进展为完成。数据使用既有加密分片格式。
不同课次发布发生竞争时只做普通快进推送；确认远端已变更才刷新重试，最多 8 次，不强推。
失败的加密结果和恢复指针仍保留；课程失败仍使整个 workflow 显示失败。
目录与订阅信息在批次收尾更新，空课次队列也保留目录同步。

邮件只有两个开关均为 true 才执行，先发布课程状态，再从刷新后的数据库按原逻辑发送。
每次成功发送即保存加密回执，重试先恢复回执再检查未发送列表，之后补发布 emailed_at。
SMTP 不提供恰好一次保证：若服务器已接收、客户端尚未来得及保存回执就中断，仍有重复风险。
不能将这样的模糊结果宣称已获得恰好一次投递。

## 验证与合并范围

手动入口可设置 `validation_course_id`，默认验证该已订阅课程最新的实际可播放课次。
`validation_lecture_rank` 可选择倒序第几堂实际录播；`validation_before_date` 可限定严格早于指定日期。
固定课时排除始终生效，无录播的假期／调休记录不计入可播放顺序。
此模式强制 `publish_results=false` 和 `send_email=false`，跳过未来排课、无录播的调休/休假
记录和删除标记；播放状态提示不作为硬门槛，仍按原 API 回退链验证 URL。
课次选择在队列中冻结，重试不重新选择课程。使用独立空数据库完成新 ASR、PPT、复核和摘要，
原历史数据库保存在加密队列里，不清空线上记录。公开审计产物只含日期、跳过数量、状态及
时长/字符数/额度计数，不包含课堂内容、课程名称、课次编号、播放 URL 或凭据。
隔离发布仍使用原 scoped merge 并保护历史；新识别结果以加密 state 产物为准。
正式汇总只接收配置中的三家模型所需的密钥及 Base URL，不将全部仓库 Secrets 打包透传。
新增自定义模型凭据时须同步更新 reusable workflow 的显式声明与转交名单。

测试覆盖正常保存、摘要失败恢复、缺失分片禁止摘要、加密状态恢复、未知云端调用不退款重试、
历史保护、PPT 进展、跨课次拒绝及真实本地 Git 发布冲突。验证使用临时 SQLite、本地 Git 仓库
和合成识别结果，不登录课程、不加载 ASR 模型、不访问云端或 SMTP。
新增 GitHub 验证工作流同样只运行这些隔离测试。

已完成一堂约 109 分钟录播的真实隔离验证：Linux Runner 上的准备、PPT、共享 ASR（62 块）、
复核、非空摘要、LectureRunner 保存及隔离发布连通。实际正式发布、SMTP 发信及真实故障恢复
未在这次课堂验证中执行，不能把流程完成当作识别准确率听审通过。摘要后续调整另有回归测试与 CI。
运行记录见 [整课隔离验证](https://github.com/Lucasuiii/Fudan_iCourse_Subscriber/actions/runs/37410686897)。

# AAC 接入正式音频准备流程

本分支按用户后续授权，将已验证的 AAC 多区间获取接入 `AudioDownloader`，不再仅作为探索 CLI。默认 `AUDIO_ACQUISITION=aac_auto`；`AUDIO_ACQUISITION=mp4` 可在进程启动前显式选回现有签名范围 MP4 路径。

正式分片准备、资源获取、单 Runner 识别与下一堂音频预取均要求保留时间轴。`AudioDownloader.schedule(..., preserve_timestamps=True)` 在自动模式中优先尝试 AAC；显式使用 `preserve_timestamps=False` 的底层兼容调用仍执行旧逻辑。模型、VAD、复核、摘要、加密恢复产物及发布流程继续消费原有 PCM／FLAC 接口。

## 获取、解码与完成判定

先读有界整轨索引，检查样本数、时长总和、音频偏移、简单 edit 和 AAC 配置；在创建 FFmpeg 前还验证第一批音频响应。默认每批至多 64 个范围、256 KiB 载荷及 4,096 个 packet，沿用冻结来源、条件范围请求、签名更新、有限重试、一次会话恢复与身份核验。

完整验证后的批次通过 stdin 送给 FFmpeg，不写 AAC 或 sparse MP4 文件。FFmpeg 将原媒体前置空白恢复到 PCM 时间轴、按已验证的音轨终点裁去最后 AAC 帧的编码填充，再重采样为 16 kHz 单声道 f32le。当前支持的时间表没有内部时间缺口，正常 AAC 帧为 1,024 个采样点，末帧可短于 1,024；复杂 edit、priming、内部缺口和未知时间表不通过此重建路径。

PCM 继续写原调用者的临时路径，供 VAD／识别边读边处理。`AACDecodeProcess` 保持消费者使用的 `poll/wait/returncode/terminate/kill/stderr` 接口；只有网络生产、全部 packet 覆盖、FFmpeg 退出及 PCM 终点检查全部通过，才报告退出码 0。不能把“部分 stdin 已足以让 FFmpeg 正常退出”当作整堂成功。

既有完整性门禁保留；AAC 另需预期／实际 packet 数完全相同、整轨覆盖和时间轴状态为真，PCM 与索引终点相差不超过 1 ms。该容差只覆盖整数采样和重采样舍入，不能豁免缺包、网络错误或解码错误。索引提供的音轨终点也写入兼容 Duration 头，供现有 VAD 和音频诊断读取；不拿视频尾端填充音轨。

AAC 正式获取预算为 90 分钟、1 GB 媒体响应体、10,000 次范围请求、500 MB 原始 AAC 载荷；单个网络读受 10／15 秒连接／读取超时约束，原准备流程 5 分钟 PCM 无进展门槛保留。索引仍默认最多 16 MiB、估算展开内存 128 MiB、100 万样本。探索 CLI 自己的 600／1,800 秒及窗口预算不变。

## 回退与取消

只有明确不支持的格式或索引／载荷资源形态可以在**输出前**回退，例如非 AAC、fragmented、多音轨、复杂编辑或超出索引预算。完整允许列表是 `src/runtime/aac_audio.py:FALLBACK_CODES`。未知格式／表损坏、来源变化、缺 part、HTML、未履行范围请求、身份失败和网络错误不获自动回退豁免。

回退继续使用同一 transport 的冻结媒体路径、总长度、ETag／Last-Modified、会话及已经使用的一次恢复预算。它仅切回原来的连续范围 relay；不会重新选择课堂来源、清除终止错误或创建新的重登录额度。探索型 body／总时限改为原 MP4 relay 的行为；正式准备自己的总时限和无进展检查仍有效。

输出后发生任何失败直接停止，保留固定错误及已取得的计数，不追加另一条获取路径。取消关闭网络生产和 FFmpeg，等待完成后由既有 `release/shutdown` 删除 PCM，并释放并发槽位。正式失败恢复是否保留加密 FLAC 仍由已有生产流程管理，不擅自删除恢复产物。

## 黑板及课件兼容

音频获取不改变 `ICourseClient.get_video_url/get_stream_params` 或作业视觉模块。语音线索仍按原视频时间触发平台截图和原视频抽帧，覆盖口述后的延迟板书；黑板模块不会读取 PCM 或只有音轨的参考容器。获取 AAC 后仍需要访问原视频，抽帧流量单独存在。

回环 HTTP 集成测试实际获取并解码 A/V 媒体中的 AAC，然后通过未修改的视觉模块再次访问原视频并抽帧。OCR 使用桩，证明接口兼容，不冒充真实黑板模型识别效果。仅板书、不口述的作业发现能力仍是既有流程的限制。

## 验证边界

新增 9 项测试覆盖实际 HTTP／FFmpeg 的原 MP4 PCM 比较、21 ms 前置 edit 和末帧终点、ALAC 输出前回退及同源条件请求、缺包／来源变化拒绝、输出后失败、索引阶段取消、生产阶段取消、完整性门禁和公开诊断脱敏。原 MP4 relay 回归显式选择 `audio_mode='mp4'`，继续验证旧路径。全仓库 751 项通过（109.276 秒）。

本机真实正式路径验证结果另见[匿名实测统计](experiments/aac-production-campus-direct.json)。未派发 Actions、调用真实 ASR／LLM、写正式数据库、发邮件或合并本分支；校园直连证据不能证明 WebVPN／Actions 性能或黑板模型效果。早期探索及原始 ABBA 结果见[实验说明](aac-range-exploration.md)。

2026-10-09 正式 `AudioDownloader` 本机校园直连整堂实测通过：627,068 个 packet 全覆盖，AAC 156.14 MB，全部媒体响应体 210.43 MB，6,556 次范围请求、6,532 个 multipart 批次，零重试／会话恢复。总墙钟 390.455 秒，约 6 分 30 秒；PCM 13,377.4713125 秒，索引终点 13,377.471333333333 秒，差约 0.021 ms。`timeline_preserved=true`、整轨覆盖和终点检查均通过，退出码 0、解码错误计数为空。本次未保存第二份完整 PCM 用于散列对照；原 MP4 对照来自前述独立探索和实际合成源回归。

实测约 52 秒时已生成约 12.5 分钟 PCM，验证生产接口会在整堂获取结束前输出数据。本次仅运行获取／解码／完整性门禁，未运行真实 VAD、ASR 或黑板模型。实测外层 30 分钟时限，并将取得 handle 后的媒体 body 预算收紧为 400 MB；这只影响验证资源上限，批次、解码、完成判定和清理均使用正式代码。

私密临时 PCM、合成参考媒体及本次临时验证脚本已删除，结束后本任务临时目录模式均为 0；保留代码、回归测试源码、匿名统计与说明。[回归统计](experiments/aac-production-regression.json)记录完整测试结果。

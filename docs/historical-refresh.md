# 历史课程更新：先预览，再确认覆盖

入口为 Actions 中的 **Historical Lecture Refresh**，只有手动运行。`preview` 重新获取指定录播、完整识别并生成摘要，保留旧正式结果；`apply` 是一次单独的手动确认。两步均不发送邮件，自动扩词保持关闭。

每批仅一个已订阅课程，最多五个明确的课次 ID。选课依据固定 ID，不使用“最新第几堂”；平台上的日期与已有记录必须一致。已有完整摘要、转录和处理状态才可进入此入口，删除或不完整的课次仍走原恢复流程。

## 预览

在本地仓库生成接收密钥（需要 `cryptography`）：

```sh
python -m scripts.history_review_client keygen
```

只会显示公钥；私钥保存在 `.history-refresh/review.key`，文件权限为 0600，该目录已排除出 Git。不覆盖已有私钥；另一次预览可以复用公钥，或用 `--private` 指定新的本地路径。

在 Actions 选择工作流与代码分支，填入：

| 输入 | 内容 |
| --- | --- |
| `action` | `preview` |
| `targets` | 例如 `{"course_id":"38404","lecture_ids":"123,456"}`；示例课次 ID 仅为占位，填写实际 `sub_id` |
| `recipient_public_key` | 上一步显示的公钥 |
| `source_run_id`、`approval_sha256` | 留空 |

指定 ID 可从现有数据查看器的录播信息取得；不根据日期猜测 ID。预览共用每日任务的锁、共享队列、最多五个活跃课次及十五台总 Runner 预算。每堂最多六台 ASR Worker，云复核仍受 900 秒／40 段限制。重新下载音频，不依赖已删除的旧测试输入。重试同一预览时沿用原选择和检查点，不偷偷换课。

完成后下载 `icourse-history-review` artifact，包含：

- `comparison.enc`：为本地公钥加密的新旧转录、摘要和新复核记录。
- `approval.enc`：为数据库密钥加密的候选数据库与确认清单，不需要在本地解密。

在本地读取对照（把 `SOURCE_RUN_ID` 换成预览 run ID，并填写解压后的文件路径）：

```sh
python -m scripts.history_review_client read \
  --input /path/to/comparison.enc --source-run SOURCE_RUN_ID
```

对照保存在 `.history-refresh/comparison.md`，权限为 0600。检查缺段、术语、公式与作业信息，确认新结果适合替换后，再进行下一步。完整性门禁证明流程完成，不代表文字准确率已获人工保证；没有自动质量评分替人决定。

对照沿用现有加密导出的 2 MiB 大小上限；超过时预览会停止生成确认包，应缩小批次，不会丢掉部分正文后继续覆盖。

## 确认覆盖

再次手动运行同一工作流：

| 输入 | 内容 |
| --- | --- |
| `action` | `apply` |
| `source_run_id` | 已完成且成功的历史预览 run ID |
| `approval_sha256` | 已查看对照中的确认指纹 |
| `targets`、`recipient_public_key` | 留空，覆盖阶段不能重新选课 |

只接受本入口的隔离预览，核验父子任务身份、固定提交、完整识别及复核、候选内容指纹。预览失败、取消、缺少或过期产物均拒绝覆盖。

覆盖前读取最新正式数据库，对照所有目标的旧状态指纹，包含正文、PPT、处理状态、删除状态及邮件回执。任何目标变化都停止整批；其他课程在预览后更新不影响目标校验，其最新结果继续保留。所有目标先在临时 SQLite 事务中一起更新，不逐堂发布部分结果。

先上传 `icourse-history-backup-ATTEMPT` 加密备份，保存覆盖前的完整正式数据库、原 data revision 及确认清单；然后重新下载核对上传的备份。缺失、上传失败或内容不一致时不发布。最后仅对备份时的 data revision 做普通快进提交，不强推；期间任何 data 更新都会中止，需重新 `apply` 以生成新备份。目标本身若已变化，则需要重新预览。

替换转录、摘要、处理结果、PPT 和该课次的处理元数据；保留课程/课次身份、日期及原邮件和失败通知回执，增加重试代际，避免旧任务回写。同一确认指纹有持久标记，重复 `apply` 不会再次覆盖，也不会覆盖第一次更新后的新结果。原本没有邮件回执的课次仍受原日常邮件规则管理；此入口本身始终不发信。

## 保存与恢复

预览对照和确认包保留 14 天，原音频/处理链输入按现有 7 天产物规则保留；本入口不自动删除正式恢复输入或 owner 日志。覆盖备份保留 90 天，公有 Git data 分支也保留旧提交历史。备份以覆盖 run ID、槽位 0 和 `history-backup` 角色绑定，可在授权恢复时使用原数据库密钥解密；不会上传明文数据库或本地私钥。

公开审计只含状态、数量、确认指纹和发信/发布开关。选课参数在计划执行前遮蔽，正文与日期仅存在加密对照或本地私密文件。手动输入仍由 GitHub 承载，此措施不把公共 Actions 仓库变成私有服务。

本入口的本地/CI 验证使用合成 SQLite、加密产物和本地 Git，未自动运行真实课堂。合并代码只使入口可选，不自动开始历史重跑或覆盖。

## 小识别缺口

新结果可保留整堂累计严格小于 15 秒的明确识别缺口；摘要与加密新旧对照均显示缺失时间段和“不完整”，不会将其标成完整转录。已确认失败的豆包补识别仍记录失败并占用原额度，不会重发或退款。历史审核只接受落在这些缺口内的失败补识别；未知调用、其他复核失败、缺口达到 15 秒及以上，仍拒绝进入覆盖审批。音频完整性、冻结来源、显式批准指纹和旧结果冲突检查保持生效。

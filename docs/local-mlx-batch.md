# 本地 MLX 双块调度

本机入口新增 `--mlx-batch-size 2`（放在 plan/run 子命令之前），默认1；该选项冻结进 manifest，恢复时必须保持一致。只改变本地Apple GPU原始块的ASR调度：一个bf16模型，双路文本解码、音频编码仍串行，使用mlx-qwen3-asr 0.4.4。单路尾块沿用原适配器，不影响main的PyTorch/GitHub调度。

两个原始块保留各自原生低能量<=30秒子切块、中文/术语/2048 token、位置和左填充mask，以及独立EOS。回显调用同一有界去提示重试，截断/超时进入原 `_recognize_resilient` 的完整无提示重试与30/15/短叶子救援，仍失败记缺口；每块独立落盘。原生/形状/OOM错误传播，不盲目重试。已完成块不会重新领，恢复时仅对未完成块配对。组初始化时间按两块分摊，记录共享初始耗时、预算和回显/截断/超时，不能把两份共享耗时各算一次。

AAC、PPT/OCR、缺口处理、CPU对齐、局部语音复核、作业视觉证据、精选配图、摘要与生成后自审均复用原流程。batch_size进入spec和候选完整性验证。既有冻结计划不能直接改代码后run；如用户明确批准续跑，必须另建控制目录、保留原计划和输入，并记录源身份/调度变更与已核验检查点的迁移来源。

验证：848项全套通过；真实首堂的首两块验证8.90秒、MLX峰值4.60GiB，复现首块术语回显后去提示补救得到low_information，第二块recognized，无缺口。此短验证只证明补救路径，不作为整堂性能；此前107分钟整堂对照为19.35→14.62分钟，耗时减少24.46%，数学差异待后续完整证据复核。

# 内嵌 AAC 实验结果

> 本文记录早期一分钟／十五分钟前缀阶段。2026-10-09 后续追加授权的整堂实测已成功获取约 223 分钟音频，并通过整轨 packet 与完整 PCM 一致性检查；整堂未复现下文的 21 ms 前缀尾差。详见[整堂后续报告](aac-full-result-zh.md)。本文原始观察和当时验收边界保留。

已在独立分支 `codex/aac-range-exploration` 完成有界实验模块、回环 HTTP 故障回归，以及校园直连一分钟 → 十五分钟 ABBA 测试。正式获取路径保持原样。测试日期为 2026-10-09；基于本地 `60746ee`，无推送或 PR。

**确认的收益是节省响应体流量；没有速度提升证据，生产时间轴验收尚未完成。**

MB 为十进制，正文流量包含 multipart 包装，不含 HTTP/TLS 头、认证/API 流量或底层重传。基线是同窗口的连续音视频字节跨度，不是正式整堂 `AudioDownloader` 的端到端性能。索引另读 9.198 MB；成功主实验索引 2.25 秒、总墙钟 514.68 秒。读取整轨音频索引以严格验证所有计数和偏移；没有下载整堂载荷。

一分钟 2,812 个、十五分钟 42,187 个 packet，四轮 AAC 字节一致；FFprobe 使用原音轨元数据独立验证每包偏移、大小、SHA-256、PTS、DTS、duration。两种解码均返回 0、无错误，PCM 公共前缀一致（排除较短结果最后 32 个重采样输出样本）。

**发现并保留的问题：** 原媒体有 21 ms 前置 empty edit。原生 packet 时间轴一致，参考 MP4 前缀与显式补偏移的 ADTS 探针的 PCM 长度仍差 **21 ms**：一分钟 59.9893125／60.0103125 秒，十五分钟 899.9893125／900.0103125 秒。该差异在合成前置编辑夹具及实测中复现，精确尾端原因尚未解决，不能称为完整 PCM 时间轴一致。原始统计的 `success=true` 只表示载荷获取、逐包覆盖、参考 packet 与有界解码检查通过；`timeline_preserved=false`。派生统计及加固后一分钟复测进一步明确 `pcm_end_match=false`、`timeline_alignment_complete=false`。

十五分钟第二轮多区间读取明显变慢，未发生该轮重试；没有保存足以定位耗时来源的逐批/链路诊断。不能将其归因于已证实的限流、磁盘、签名或并发问题。经用户明确允许，本机登录/实测与云端同账号任务可重叠，本轮不能证明互踢或无互踢。

后续 `read1` 滴流时限加固又做一次一分钟实测，全部 2,812 个 packet 再次通过，21 ms 尾差仍存在。加固复测索引 35.05 秒，多区间 4.62／1.73 秒、连续基线 0.96／1.39 秒；进一步说明时间波动不能忽略。未重复十五分钟以增加额外流量。

累计九次凭据流程（含索引/协议开发失败阶段）、1,317 次范围请求、**695,794,294 字节媒体响应体**，低于本次累计 700 MB body 预算。每次有限认证与请求均通过现有身份/来源机制，没有秘密输出；真实会话恢复本轮为零次，恢复成功证据来自回环模拟，不冒充校园恢复验证。失败阶段没有进入十五分钟；七次失败过程的匿名错误/流量已合并保留。

支持非 fragmented、单音轨 AAC-LC、标准采样率和单/双声道、stsz/stz2、stco/co64、严格完整索引；简单零媒体起点的 edit、可选前置空白与已知 roll 分组。有 roll preroll 时只支持从零获取前缀。复杂编辑/priming、随机起点 preroll、时间缺口、加密、多音轨、未知结构明确拒绝。完整支持范围和验证方法见[实验说明](../aac-range-exploration.md)。

全仓库通过，新增 21 项测试覆盖合成 MP4、真实 FFmpeg 夹具和回环 HTTP；包括乱序、缺失/重复/额外 part、边界、压缩、200/416/429、截断、有限重试、身份恢复后来源变化、取消、滴流时限、计数/偏移/内存预算及“少末包仍能解码但不能成功”。测试环境复用已有 Cairo/Node 路径，未安装或修改共享配置。最终精确测试计数/耗时见[回归统计](aac-local-regression.json)。

整堂、WebVPN、Actions、完整尾部/priming、字幕/PPT/VAD 对齐，以及可靠生产回退均未验收。下一步应先解决 PCM 尾差、输出保留时间信息的正式容器、增加逐批耗时指标，之后再按单独授权扩展测试。

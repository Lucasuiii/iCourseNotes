# 单堂课 ASR 共享队列

本版本将 `parallel_pilot.yml` 的手动和定时默认设置为 `shard_mode=shared`；自动术语仍默认关闭。
原共享块队列已有实际课堂验证；新增全局派发器的验证范围见 [全局 Runner 调度](global-runner-pool.md)，不能沿用旧整课结果宣称新派发机制已完成云端验证。

## 调度范围和数量

共享范围仍为**一堂课的原始 VAD 块**。Runner 每次领取一个块，保存结果后再领取下一个，优先领取音频较长的块。空闲 Runner 可以领取本堂课剩余的任何块，不受原静态分组限制。

调度数量依据 `剩余原块累计时长 × 估计推理秒数/音频秒数 ÷ 4500` 向上取整，最多六台，也不超过块数。估计优先参考同课程更早、同模型版本的已完成记录；本堂至少五个块有耗时后改用实测中位数；无历史时暂取 2 倍实时。4500 秒是约 75 分钟 ASR 的初始目标，不含准备、排队、安装、复核和摘要，也不保证在该时间完成。

不可变计划最多保留六个**装配分组**，实际启动的 Worker 数由全局调度器决定；分组数不能当作实际机器数。
全局同时最多一台控制器和十四个子任务，最多五个活跃课次、单堂最多六个 ASR Worker。准备、识别、汇总和发布都占用同一个预算；排队或派发结果未知的子任务也占预留名额。完成的课堂优先独立汇总和发布，其他课次继续识别；空出的名额可以补给长课，不重切音频或领取已完成块。

固定 `2` 和 `auto` 保留旧流程及每堂最多三路的限制。日常与手动入口共用已有批次锁；新全局流程还记录所有子任务，控制器被取消或中断后不能借此释放仍在运行的子任务额度。恢复必须重试父工作流，不能单独重试子工作流。

手动资源获取入口也共用 `icourse-data` 批次锁并保留排队任务，避免与课堂／每日入口额外并发登录；推送注册任务使用独立锁，不执行获取。取消本地音频启动会停止槽位等待、关闭尚未完成的媒体中继，旧任务和重试任务使用不同临时音频路径。媒体及现有会话探测的 TLS 错误停止，不按普通连接错误重试或再提交密码认证。

## Actions 进度显示

展开“课堂并发进度（获取 → 识别 → 汇总）”任务中的“实时课堂进度”日志，可查看每个匿名课次的阶段、完整成功块数、缺失块数、待领取／识别中块数、Worker 运行／等待数量和子任务链接。状态或计数变化时立即输出，其他等待每两分钟输出一次心跳；准备阶段完成前不虚构块数或预计完成时间。

步骤结束后生成 GitHub 摘要表，并将 `pool-progress.json` 与 `pool-audit.json` 一起保存。识别缺失与调度失败仍按原有门禁处理；进度显示异常不触发重派、改变队列或隐藏原错误。公开内容仅包含计数、匿名课次和已核验子任务身份，不包含录播标题、音频地址、识别正文、私密计划或异常原文。

## 原始输入和汇总

- 使用现有 Silero VAD 和约两分钟切片，保留原始时间戳及播放回退链。正式分片链解码使用 `aresample=async=1:first_pts=0`，在转成无时间戳的 PCM 前按音轨时间戳补齐间隙，防止间隙被压掉后字幕、作业截图定位前移；不会按照视频声明时长人为追加尾部静音。传统单 Runner 入口的解码命令保持原样。
- 保留整段音频 SHA-256、逐块 FLAC SHA-256、模型版本、课次和冻结词表；仅复用已读的音频字节计算哈希，未取消完整性检查。
- 每台 Worker 连续领块期间保留 Qwen 模型，退出时释放。豆包只在统一汇总阶段参与疑难复核，沿用整堂课共享的现有额度，分片不能各自获得一份额度。
- 全部原计划块完成后才允许汇总。静态 shard 分组继续作为结果校验和装配接口，不能限制动态领取，也不能被当成实际 Worker 的耗时统计。
- 原始排序、边界去重、LectureRunner 保存及恢复、独立发布接口保持不变。私密原始 Qwen 导出可直接读取完整共享队列结果，仍不调用模型。

## 持久化和故障恢复

每个 run/task 使用独立 orphan Git 分支 `codex/asr-queue-<run_id>-<task_slot>`。分支树只有 `queue.enc`，包含经过 AES-GCM 加密并绑定 repo/run/task 的状态及识别文本；不存音频、明文课堂内容或密钥。不会修改 main/data。ASR job 因此需要 `contents: write`，用途限定在该临时协调分支。

领取与完成采用乐观并发：候选提交只以读取时的版本为父提交，普通 Git push 遇到竞争更新会被拒绝，重新读取后重试；禁止 force push。网络错误与确定不存在分开处理，不能因读取失败而重建空队列。

已领取块没有按墙钟过期的租约，较慢的推理不会被另一台机子抢走。新父 Actions attempt 才能接管旧代际的未完成领取；调度器必须先确认全部旧子任务已结束。失败只补未持久化完成的块。

识别完成先写本地加密 `shared-local.enc`，再保存远端队列。远端保存失败时保留领取状态，防止同一 attempt 的其他 Worker 再识别这个已落盘的块。Actions 的 always 上传步骤保存本地检查点。下一 attempt 的**每台** Worker 都先恢复所有旧 Worker 的本地结果，才允许领取任务；避免恢复速度不同造成抢先重复解码。成功分片的旧检查点也纳入恢复。

硬终止发生在解码完成但任何持久化之前的那一个块仍可能需要重做，无法承诺进程内结果必然可恢复。检查点缺失、过期、输入不符、当前领取仍活跃或结果冲突时停止，不能默认为全新输入。跨 run 恢复还要求旧 run 已结束，复用原音频、全部已完成文本和现有复核额度检查点，不重置云端额度。

`qwen-production-shared-*` artifacts 保留 7 天。全局流程把准备、Worker 和汇总产物保存在对应子 run，派发记录用于从父 run 自动定位；加密内容仍绑定父 run/task/stage，实际 Actions run ID 不被覆盖。协调分支目前保留供恢复/原始文本导出，尚未自动清理；每次状态更新会增加加密 Git 历史。实际整课验证已覆盖队列保存；仍需持续观察 Git 往返与历史存储开销，并设计不影响恢复窗口的清理策略。

准备阶段在时长校验之前保存原始样本对应的 FLAC、哈希、实际/媒体时长、差值、解码退出状态及冻结词表；解码或校验失败也保留已获取音频供诊断。校验失败不创建 ASR 队列，重试不会重新获取已有失败音频，也不会认可不完整输入。公开验证审计仅输出数字、哈希和状态；音频、课次详情和词表仍在加密 artifact 中。只读 `inspect_audio` 可导出尚未生成分块计划的失败音频用于诊断。

修复后需要重新获取原先未保留音频的失败课堂时，显式使用 `validation_source_run_id`。它只允许已结束且准备失败、没有音频/ASR 计划或复核状态的正式隔离试跑；沿用原队列中的唯一课次、空数据库、原历史及冻结词表，重新绑定到新 run。课程、倒序位置、截止日期或术语模式不匹配时拒绝，不重新选择最新课。发布和邮件必须关闭；已有音频或识别结果应走恢复路径，不能通过此入口重置识别或云端额度。每次新获取仍需用户授权。

## 验证边界

隔离测试覆盖全局预算、空闲容量补给、独立汇总、未知派发不重放、父级恢复，以及快慢 Worker 动态领块、真实本地 Git 并发写入冲突、加密绑定、失败恢复不重复解码、未完成禁止摘要、原时间线和冻结词表。测试中的 Qwen 推理结果使用替身，不代表真实课堂识别质量或提速幅度。工作流的准备、模型安装、排队、协调保存、ASR、复核和发布开销需要分别统计。

一堂约 109 分钟录播中，3 台 Worker 完成全部 62 块，并成功进入复核、摘要与隔离发布。
这证明共享流程连通，不构成与前一堂不同输入的严格 A/B 提速或准确率结论。
对应的私密验证记录保留公开阶段证据；
真实 Runner 硬终止与云端额度未知场景仍以隔离故障测试为主要证据。


## 单块生成上限与缺失区间

Qwen 普通生成仍为 2048 token；术语回显的去提示重试仍为 256 token。识别器同时检查实际生成 ID 数及解析文字的保守上限余量（8 token），截断／超时输出不进入结果。安全诊断区分生成上限与保守文字门禁，并记录原块编号、原时间段、失败生成阶段及重试片段。

仅对生成上限、回显重试超时或未解决回显启用局部容错：一次原长度、无术语提示、2048 token 重试；失败后缩到 30 秒，再按需缩到 15 秒。原块不超过 30 秒时直接缩到 15 秒，不超过 15 秒时不重复相同片段。120 秒块最多 14 次识别调用；包含重叠的 122 秒块最多 15 次（若首次触发回显，额外一次原有回显重试）。每次补救合作式时间上限为 min(600 秒, 60 + 8 × 片段秒数, Worker 剩余时间)，仍受原 Worker 总预算限制；单次原生前向可能超过合作式截止时间。

普通生成同样在每步检查 Worker 剩余时间；回显重试取原 60 秒与剩余时间的较小值。超时返回的文字全部丢弃，预算耗尽记录 `worker_deadline` 缺失，不启动后续补救。生成方法和 token 上限在异常／超时后恢复；这仍是合作式边界，不能强行中断单次原生前向。

完整成功片段可保留，失败输出全部丢弃。仍失败时结果携带 `missing_intervals`，队列状态为 `failed`；它是终态，不再被其他 Worker 或更高 attempt 自动领取、覆盖或改成成功。普通未知异常、模型加载、内存、损坏音频及协调失败仍传播，防止把基础设施问题伪装成课堂缺失。

Worker 可正常结束并继续其他块；其正常结束只表示本次任务排空。控制器区分 `settled`（无待处理块）与 `complete`（无缺失），排空后进入 gather 生成缺失审计。gather、跨 Runner 结果组装及本地直读入口均拒绝缺失课堂的摘要／完成标记，`asr_complete=false`、processed／邮件状态保持未完成。局部文本只留在加密队列／检查点；公开审计只含编号、时间、原因与计数。

对于历史泛化失败，可用受限 `inspect_block_failures` 只读查看已结束批次和全部已结束子任务的加密 claim/release 历史（最多 128 个状态），导出最近释放的失败块位置。数据库密钥留在 GitHub Runner；无媒体下载、识别、登录、邮件、发布或队列修改。旧代码未记录失败时的生成 token 数与阶段时，不应将推测的 2048／256 档当成已证实。

## 认证 JSON 响应异常

登录仍沿用原有最多三次完整认证、5／10 秒退避与最终 iCourse API 验证。认证方法、公钥或 `authExecute` 的 JSON 解析失败会记录安全的 HTTP 状态、响应类别（空／HTML／JSON 外形／其他）、挑战提示和跳转标记，不公开正文、URL、Cookie 或认证上下文。

仅无跳转且无挑战提示的 HTTP 200 空／损坏 JSON，或 408／429／500／502／503／504 异常响应，允许关闭旧 Session 后重新建立完整认证；不复用旧上下文或重发已用票据。200 未知 HTML、其他明文、明确认证拒绝、验证码／二次验证、TLS 异常保持停止。媒体恢复入口原有一次完整认证上限保留。仍失败就保留原始异常类型和逐次安全审计，不能标记登录成功。
